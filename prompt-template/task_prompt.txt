Task: download EVERY supplementary file that could be the STUDY PROTOCOL or
STATISTICAL ANALYSIS PLAN (SAP) — including a combined "Supplementary Appendix" or
any document-type supplement you are unsure about. An automated check afterwards
keeps the genuine protocol/SAP and discards the rest, so err toward including a
borderline file; missing the real protocol is the failure to avoid.

Identify each file by the DESCRIPTIVE TEXT next to its link (caption, list-item,
or heading) — NOT the link text or file name, which are often generic (e.g.

Trial Protocol and Statistical Analysis Plan" -> download that file.

Steps:
1. If a Cloudflare check or a pop-up / cookie / consent overlay blocks the page,
   clear it (wait it out, or click Accept / Close / the X).
2. Open the supplementary-materials section (a link like "Supplementary Material",
   "Supporting Information", "Appendix", or "Additional files"); do not read the
   article body. Publisher notes:
{publisher_notes}
   Once you have READ a panel/section, trust its contents and move on — do NOT
   re-open the same panel to re-read the list. (This does not excuse you from
   checking that a download actually happened; see step 4.)
3. For each supplement entry, read its description and download every one that is

4. Confirm each file REACHED DISK before you finish. A click that logged no
   download saved nothing — on many publishers the link beside a supplement just
   opens the PDF in the browser's viewer. The only proof is the file appearing in
   available_file_paths; the page giving no error is not proof, and neither is
   the PDF being on screen. For anything not yet there, open the PDF itself and
   use the VIEWER's own download/save control, then check again.

Do not download the main article text, or supplements that are clearly ONLY
figures, tables, data, or consent forms. Download each file once; finish once all
candidates are downloaded.

To finish, call done with BOTH of its fields: "text" — one sentence naming the
files you downloaded, or stating that no protocol/SAP was found — and "success".
The prose goes in "text"; there is no "message" field. Name a file in "text" only
if you saw it in available_file_paths. If a candidate existed but you could not
get it onto disk, say so and use success=false — that is a useful result, whereas
claiming a download that did not happen is the worst outcome here.
